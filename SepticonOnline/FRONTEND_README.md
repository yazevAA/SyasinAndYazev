# Septikon Online — Frontend старт

## Статус

Это стартовая инструкция для frontend-разработчика. Backend написан на Go, модуль — `septikon-online`. Последний сообщённый результат `go test ./...` был успешным, но перед интеграцией тесты необходимо повторить на актуальной версии репозитория.

## Предлагаемый стек

- React
- TypeScript
- Vite
- CSS Modules или обычный CSS на первом этапе

Это предложение, а не уже принятое техническое решение. Перед созданием проекта согласуйте стек с frontend-разработчиком.

## Подготовка окружения

1. Установить актуальную LTS-версию Node.js.
2. Создать приложение React + TypeScript через Vite.
3. Установить зависимости проекта.
4. Создать `.env` на основе `.env.example`.
5. Запустить Go backend на `http://localhost:8080`.
6. Проверить `GET http://localhost:8080/health`.
7. Запустить frontend dev server.

## Переменные окружения

```env
VITE_API_BASE_URL=http://localhost:8080
```

Не добавляйте завершающий `/` в значение `VITE_API_BASE_URL`, если API-клиент сам формирует пути.

## Порядок реализации

1. **API-клиент.** Общая функция запросов, обработка ошибок, базовый URL.
2. **Комнаты.** Список, создание, подключение.
3. **Ожидание игроков.** Отображение состава комнаты и статуса.
4. **Состояние игры.** Получение комнаты и отображение данных без изменения логики на клиенте.
5. **Игровое поле.** Воспроизвести точную схему из переданного изображения и правил.
6. **Ход игрока.** Отображение текущего игрока, бросок кубика, доступные действия, завершение хода.
7. **Остальные механики.** Роботы, производство, ресурсы, ремонт и ракеты — после проверки соответствующих API.
8. **Совместный тест.** Два браузера подключаются к одной комнате и видят согласованное состояние.

## Важные правила интеграции

- Не рассчитывать игровые правила на frontend.
- Не хранить отдельную «истинную» копию игрового состояния в браузере.
- После действия обновлять состояние с сервера.
- Не определять своего игрока по позиции в массиве.
- Не считать endpoint существующим, пока он не проверен в Go router.
- Не фиксировать типы TypeScript по догадке: сверить их с Go JSON tags.
- Обрабатывать ошибки сети и ответы сервера.

## Что backend-разработчику нужно подтвердить

См. `frontend-contract.md` и `project-state.json`. В первую очередь подтвердить точные маршруты, JSON-поля, CORS, выдачу player ID, а также наличие действий производства, сбора ресурсов и ракет.
