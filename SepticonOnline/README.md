
# Septikon Online

Браузерная многопользовательская пошаговая игра по мотивам настольной игры «Септикон».

Проект разрабатывается на Go. Backend отвечает за игровую логику, хранение состояния партий и обработку запросов. Frontend отвечает за отображение игрового поля и взаимодействие пользователя с игрой.

## 1. Технологии

- Go — Backend.
- HTTP API — взаимодействие Frontend и Backend.
- JSON — формат обмена данными.
- TypeScript — предполагаемый язык Frontend.

## 3. Запуск Backend

Для запуска сервера необходимо:

1. Установить Go.
2. Открыть терминал в корневой папке проекта.
3. Выполнить команду:

```bash
go run ./cmd/server
```

По умолчанию сервер запускается на:

```text
http://localhost:8080
```

Проверить работу сервера можно через:

```text
GET http://localhost:8080/health
```

Ожидаемый ответ:

```json
{
  "status": "ok"
}
```

## 4. Игровая концепция

- В партии участвуют два игрока.
- У каждого игрока есть собственная космическая станция.
- Игроки выполняют действия по очереди.
- За ход можно выполнить одно основное действие.
- За ход можно один раз бросить кубик.
- Роботы перемещаются на количество клеток, выпавшее на кубике.
- Ракеты перемещаются автоматически.
- Производство ресурсов занимает определённое количество игровых ходов.
- Ремонт повреждённых отсеков также занимает время.

### Игровое поле

Игровое поле состоит из:

- 8 подземных уровней;
- 21 отсека на каждом подземном уровне;
- 1 поверхности астероида.

Каждый отсек имеет собственный идентификатор, уровень, позицию, тип и состояние повреждения.

## 5. Ресурсы

В игре предусмотрено пять основных ресурсов:

| Ресурс | Назначение |
|---|---|
| Metal | Строительство и ремонт |
| Uranium | Топливо и энергетические процессы |
| Oxygen | Поддержание жизнедеятельности |
| Biomass | Биологические ресурсы |
| Energy | Энергоснабжение станции |

Начальные тестовые запасы каждого игрока:

| Ресурс | Количество |
|---|---:|
| Metal | 10 |
| Uranium | 5 |
| Oxygen | 10 |
| Biomass | 5 |
| Energy | 10 |

Эти значения предварительные и могут измениться при дальнейшей разработке.

## 6. Основные игровые объекты

### Player

Игрок содержит:

- ID — идентификатор игрока.
- Name — имя.
- Ready — готовность к игре.
- Station — игровая станция.
- Inventory — запасы ресурсов.
- Robots — список роботов.
- ProductionTasks — производственные задачи.

### Board

Станция содержит:

- Levels — список подземных уровней.
- Surface — поверхность астероида.

### Compartment

Отсек содержит:

- ID — идентификатор.
- Level — номер уровня.
- Position — позиция на уровне.
- Type — тип отсека.
- Damaged — состояние повреждения.

### Robot

Робот содержит:

- ID — идентификатор.
- OwnerID — идентификатор владельца.
- Position — текущая позиция.
- Active — активность робота.

### Rocket

Ракета содержит:

- ID — идентификатор.
- OwnerID — владелец.
- SourceStation — станция отправления.
- TargetStation — станция назначения.
- Position — текущая позиция.
- TotalDistance — общая дистанция.
- Speed — скорость.
- Status — состояние ракеты.

### ProductionTask

Производственная задача содержит:

- ID — идентификатор.
- Resource — производимый ресурс.
- Amount — количество ресурса.
- RequiredTurns — необходимое количество ходов.
- RemainingTurns — оставшееся количество ходов.
- Completed — завершено ли производство.

### RepairTask

Задача ремонта содержит:

- ID — идентификатор.
- OwnerID — владелец.
- CompartmentID — идентификатор ремонтируемого отсека.
- RemainingTurns — оставшееся время.
- Completed — завершён ли ремонт.

## 7. Очередность ходов

За один ход игрок:

1. Бросает кубик.
2. Выполняет одно основное действие.
3. Завершает ход.

После завершения каждого хода:

- Продвигаются летящие ракеты.
- Обновляются производственные задачи.
- Продвигаются ремонтные задачи.

Важно: игровые процессы обновляются после каждого отдельного хода игрока, а не после полного круга из двух игроков.

## 8. HTTP API

Основные маршруты:

| Метод | Endpoint | Назначение |
|---|---|---|
| GET | /health | Проверка сервера |
| GET | /api/rooms | Получение списка комнат |
| POST | /api/rooms | Создание комнаты |
| GET | /api/rooms/{id} | Получение комнаты |
| POST | /api/rooms/{id}/join | Подключение к комнате |
| POST | /api/rooms/{id}/game/roll | Бросок кубика |
| POST | /api/rooms/{id}/game/end-turn | Завершение хода |
| POST | /api/rooms/{id}/game/move-robot | Перемещение робота |
| POST | /api/rooms/{id}/game/repair | Начало ремонта |

Подробное описание запросов и ответов находится в файле `frontend-contract.md`.

## 9. Ограничения текущей версии

- Игровые комнаты хранятся в оперативной памяти.
- После перезапуска сервера партии теряются.
- Пока отсутствует полноценная авторизация.
- WebSocket ещё не реализован.
- Для обновления состояния игры Frontend может использовать периодические GET-запросы.
- Проверка маршрутов перемещения роботов требует дальнейшего развития.
- Не все игровые действия пока доступны через HTTP API.
