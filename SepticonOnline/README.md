# Septikon Online — Backend Documentation

**Septikon Online** — браузерная многопользовательская пошаговая стратегия, основанная на настольной игре «Септикон».

Документ предназначен для разработчиков Backend и Frontend. Он описывает архитектуру проекта, API, игровые объекты, переменные и способы взаимодействия с сервером.

---

# 1. Общая информация

## Технологии

| Компонент | Технология |
|---|---|
| Backend | Go |
| HTTP API | net/http |
| Формат обмена данными | JSON |
| Игровая логика | Go |
| Frontend | Разрабатывается отдельно |
| База данных | Пока не подключена |
| WebSocket | Планируется |

## Основная концепция

В игре участвуют два игрока. Каждый управляет собственной космической станцией.

Основные игровые механики:

- Управление станцией.
- Перемещение роботов.
- Добыча ресурсов.
- Ремонт повреждённых отсеков.
- Запуск ракет.
- Поочерёдное выполнение ходов.
- Взаимодействие двух игроков в одной игровой комнате.

# 4. Архитектура взаимодействия

Backend отвечает за:

- хранение состояния игровых комнат;
- создание и подключение игроков;
- проверку очередности ходов;
- выполнение игровых действий;
- изменение состояния станций;
- обработку ресурсов;
- проверку допустимости действий.

Frontend отвечает за:

- отображение игрового поля;
- отображение станций и отсеков;
- отображение роботов и ракет;
- отображение ресурсов;
- интерфейс управления игроком;
- отправку HTTP-запросов;
- отображение ответов и ошибок Backend.

**Главное правило:** Frontend отображает и отправляет команды, Backend рассчитывает и подтверждает игровые изменения.

# 5. HTTP API

Все запросы и ответы используют JSON.

Базовый адрес:

```text
http://localhost:8080
```

## 5.1. Проверка сервера

`GET /health`

Ответ:

```json
{
  "status": "ok"
}
```

## 5.2. Создание комнаты

`POST /api/rooms`

Тело запроса:

```json
{
  "playerId": "player1",
  "playerName": "Игрок 1"
}
```

Ответ — `201 Created`.

## 5.3. Получение списка свободных комнат

`GET /api/rooms`

Возвращает комнаты, ожидающие второго игрока.

## 5.4. Получение комнаты

`GET /api/rooms/{roomId}`

Возвращает информацию о комнате и игровой партии.

## 5.5. Подключение второго игрока

`POST /api/rooms/{roomId}/join`

Тело запроса:

```json
{
  "playerId": "player2",
  "playerName": "Игрок 2"
}
```

После подключения второго игрока создаётся игровая партия.

# 6. Справочник переменных и JSON-объектов

Этот раздел особенно важен для Frontend.

Все поля ниже соответствуют структурам Backend и их JSON-представлению. Названия в JSON используют camelCase.

Например:

- Go: `PlayerID`
- JSON: `playerId`

Frontend должен обращаться именно к JSON-названиям.

## 6.1. Room — игровая комната

Комната объединяет двух игроков и их игровую партию.

| JSON-поле | Тип | Описание | Для чего Frontend |
|---|---|---|---|
| `id` | string | Уникальный ID комнаты | Идентификация комнаты |
| `status` | string | Состояние комнаты | Отображение ожидания или игры |
| `players` | array | Список участников | Отображение игроков |
| `game` | object/null | Игровая партия | Получение состояния игры |

Возможные значения `status`:

| Значение | Описание |
|---|---|
| `waiting` | Ожидание второго игрока |
| `playing` | Игра началась |

Пример:

```json
{
  "id": "room-1",
  "status": "playing",
  "players": [
    {
      "id": "player1",
      "name": "Игрок 1"
    },
    {
      "id": "player2",
      "name": "Игрок 2"
    }
  ],
  "game": {}
}
```

## 6.2. RoomPlayer — участник комнаты

| JSON-поле | Тип | Описание |
|---|---|---|
| `id` | string | ID игрока |
| `name` | string | Имя игрока |

Используется для отображения списка участников комнаты.

## 6.3. Game — игровая партия

Это главный объект игрового процесса.

| JSON-поле | Тип | Описание | Для чего Frontend |
|---|---|---|---|
| `id` | string | ID партии | Идентификация партии |
| `status` | string | Состояние игры | Определение состояния партии |
| `players` | array | Игроки с их станциями | Отображение обеих станций |
| `rockets` | array | Список ракет | Отображение ракет |
| `turn` | object | Состояние ходов | Определение текущего игрока |
| `winnerId` | string | ID победителя | Отображение результата, если определён |

Возможные значения `status`:

| Значение | Описание |
|---|---|
| `waiting` | Ожидание |
| `playing` | Игра продолжается |
| `finished` | Игра завершена |

`winnerId` может отсутствовать, пока победитель не определён.

## 6.4. Turn — состояние ходов

Поле `turn` содержит объект менеджера ходов.

| JSON-поле | Тип | Описание | Для чего Frontend |
|---|---|---|---|
| `playerIds` | array | ID двух участников | Информация об игроках |
| `turn` | object | Информация о текущем ходе | Отображение текущего хода |

Внутри `turn`:

| JSON-поле | Тип | Описание |
|---|---|---|
| `currentPlayerId` | string | ID игрока, который сейчас ходит |
| `number` | number | Номер хода |
| `diceResult` | number | Результат броска кубика |
| `diceRolled` | boolean | Был ли уже брошен кубик |
| `actionUsed` | boolean | Использовано ли основное действие |

**Самые важные переменные для интерфейса:**

- `currentPlayerId` — определяет, чей сейчас ход.
- `number` — номер текущего хода.
- `diceResult` — показывает результат кубика.
- `diceRolled` — определяет, можно ли бросить кубик.
- `actionUsed` — определяет, выполнено ли основное действие.

Пример:

```json
{
  "playerIds": ["player1", "player2"],
  "turn": {
    "currentPlayerId": "player1",
    "number": 1,
    "diceResult": 4,
    "diceRolled": true,
    "actionUsed": false
  }
}
```

## 6.5. Player — игровой игрок

Каждый игрок содержит собственную станцию, ресурсы, роботов и производственные задачи.

| JSON-поле | Тип | Описание | Для чего Frontend |
|---|---|---|---|
| `id` | string | ID игрока | Идентификация |
| `name` | string | Имя игрока | Отображение имени |
| `ready` | boolean | Готовность игрока | Индикатор готовности |
| `station` | object | Игровая станция | Отображение поля |
| `inventory` | object | Запасы ресурсов | Панель ресурсов |
| `robots` | array | Список роботов | Отображение роботов |
| `productionTasks` | array | Задачи производства | Отображение производства |

## 6.6. Board — игровая станция

Каждая станция содержит уровни и поверхность астероида.

| JSON-поле | Тип | Описание |
|---|---|---|
| `levels` | array | Подземные уровни станции |
| `surface` | object | Поверхность астероида |

Внутри `surface`:

| JSON-поле | Тип | Описание |
|---|---|---|
| `level` | number | Номер уровня поверхности |
| `present` | boolean | Наличие поверхности |

Сейчас предусмотрено:

- 8 подземных уровней;
- 21 отсек на каждом уровне;
- 9-й уровень — поверхность астероида.

Каждый элемент `levels` содержит:

| JSON-поле | Тип | Описание |
|---|---|---|
| `number` | number | Номер уровня |
| `compartments` | array | Отсеки уровня |

## 6.7. Compartment — отсек станции

Это один из основных объектов игрового поля.

| JSON-поле | Тип | Описание | Для чего Frontend |
|---|---|---|---|
| `id` | string | Уникальный ID отсека | Идентификация отсека |
| `level` | number | Номер уровня | Определение уровня |
| `position` | number | Позиция на уровне | Расположение на карте |
| `type` | string | Тип отсека | Выбор изображения и функций |
| `damaged` | boolean | Повреждён ли отсек | Отображение повреждения |

Пример:

```json
{
  "id": "L1-C1",
  "level": 1,
  "position": 1,
  "type": "unknown",
  "damaged": false
}
```

На данный момент все отсеки создаются с типом `unknown`. Реальное распределение типов ещё предстоит реализовать.

## 6.8. Inventory — инвентарь игрока

Инвентарь хранит количество доступных ресурсов.

| JSON-поле | Тип | Описание |
|---|---|---|
| `metal` | number | Количество металла |
| `uranium` | number | Количество урана |
| `oxygen` | number | Количество кислорода |
| `biomass` | number | Количество биомассы |
| `energy` | number | Количество энергии |

Пример:

```json
{
  "metal": 10,
  "uranium": 5,
  "oxygen": 10,
  "biomass": 5,
  "energy": 10
}
```

Текущие тестовые начальные запасы:

| Ресурс | Количество |
|---|---:|
| Металл | 10 |
| Уран | 5 |
| Кислород | 10 |
| Биомасса | 5 |
| Энергия | 10 |

Эти значения пока предварительные.

## 6.9. Robot — робот

Роботы перемещаются по игровому полю.

| JSON-поле | Тип | Описание | Для чего Frontend |
|---|---|---|---|
| `id` | string | ID робота | Идентификация |
| `ownerId` | string | ID владельца | Определение владельца |
| `position` | object | Позиция робота | Размещение на поле |
| `active` | boolean | Активен ли робот | Отображение состояния |

Внутри `position`:

| JSON-поле | Тип | Описание |
|---|---|---|
| `level` | number | Уровень станции |
| `position` | number | Номер позиции на уровне |

Пример:

```json
{
  "id": "robot1",
  "ownerId": "player1",
  "position": {
    "level": 1,
    "position": 5
  },
  "active": true
}
```

Для отображения робота Frontend использует:

- `position.level`;
- `position.position`;
- `ownerId`;
- `active`.

## 6.10. ProductionTask — производство ресурсов

Производственная задача хранит информацию о процессе добычи.

| JSON-поле | Тип | Описание |
|---|---|---|
| `id` | string | ID задачи |
| `resource` | string | Тип производимого ресурса |
| `amount` | number | Количество ресурса |
| `requiredTurns` | number | Изначальная длительность |
| `remainingTurns` | number | Сколько игровых тиков осталось |
| `completed` | boolean | Завершено ли производство |

Пример:

```json
{
  "id": "production1",
  "resource": "metal",
  "amount": 5,
  "requiredTurns": 3,
  "remainingTurns": 2,
  "completed": false
}
```

Frontend может отображать:

- название ресурса;
- количество производимого ресурса;
- оставшееся время;
- состояние производства.

## 6.11. Rocket — ракета

Ракеты хранятся в общем списке `game.rockets`.

| JSON-поле | Тип | Описание | Для чего Frontend |
|---|---|---|---|
| `id` | string | ID ракеты | Идентификация |
| `ownerId` | string | ID владельца | Определение владельца |
| `sourceStation` | string | Исходная станция | Начальная точка |
| `targetStation` | string | Целевая станция | Конечная точка |
| `position` | number | Текущее расстояние от старта | Отображение движения |
| `totalDistance` | number | Полная дистанция | Определение конца пути |
| `speed` | number | Скорость перемещения | Расчёт движения |
| `status` | string | Состояние ракеты | Отображение статуса |

Возможные значения `status`:

| Значение | Описание |
|---|---|
| `ready` | Готова к запуску |
| `flying` | Находится в полёте |
| `arrived` | Достигла цели |

Пример:

```json
{
  "id": "rocket1",
  "ownerId": "player1",
  "sourceStation": "player1",
  "targetStation": "player2",
  "position": 5,
  "totalDistance": 20,
  "speed": 5,

```

## 6.12. RepairTask — ремонт

Задачи ремонта хранятся в `game.repairs`.

| JSON-поле | Тип | Описание |
|---|---|---|
| `id` | string | ID задачи ремонта |
| `ownerId` | string | ID игрока |
| `compartmentId` | string | ID ремонтируемого отсека |
| `remainingTurns` | number | Оставшееся время |
| `completed` | boolean | Завершён ли ремонт |

Пример:

```json
{
  "id": "repair1",
  "ownerId": "player1",
  "compartmentId": "L1-C1",

```

**Примечание:** в текущей структуре `Game` поле `Repairs` должно быть экспортировано с JSON-тегом `json:"repairs"`, чтобы Frontend мог получать его. Если это поле ещё не добавлено в структуру, оно пока не будет присутствовать в ответе API.

# 7. Управление игровой партией через API

Все игровые действия выполняются через:

```text
/api/rooms/{roomId}/game/
```

## 7.1. Бросок кубика

`POST /api/rooms/{roomId}/game/roll`

```json
{
  "playerId": "player1"
}
```

Ответ:

```json
{
  "result": 4
}
```

## 7.2. Завершение хода

`POST /api/rooms/{roomId}/game/end-turn`

```json
{
  "playerId": "player1"
}
```

Ответ:

```json
{
  "message": "ход завершен"
}
```

## 7.3. Перемещение робота

`POST /api/rooms/{roomId}/game/move-robot`

```json
{
  "playerId": "player1",
  "robotId": "robot1",
  "path": [
    {"level": 1, "position": 1},
    {"level": 1, "position": 2},
    {"level": 1, "position": 3},
    {"level": 1, "position": 4},
    {"level": 1, "position": 5}
  ]
}
```

Маршрут должен соответствовать текущей позиции робота и результату кубика. Проверка реальной связности клеток ещё требует доработки.

## 7.4. Начало ремонта

`POST /api/rooms/{roomId}/game/repair`

```json
{
  "playerId": "player1",
  "taskId": "repair1",
  "compartmentId": "L1-C1"
}
```

Текущие тестовые параметры:

- стоимость — 2 металла;
- длительность — 2 игровых тика.

# 8. Справочник игровых переменных для Frontend

Ниже собраны поля, к которым Frontend будет обращаться чаще всего.

| Что нужно отобразить | Путь к данным |
|---|---|
| ID комнаты | `room.id` |
| Статус комнаты | `room.status` |
| Имя первого игрока | `room.players[0].name` |
| Имя второго игрока | `room.players[1].name` |
| ID текущего игрока | `room.game.turn.turn.currentPlayerId` |
| Номер хода | `room.game.turn.turn.number` |
| Результат кубика | `room.game.turn.turn.diceResult` |
| Бросался ли кубик | `room.game.turn.turn.diceRolled` |
| Использовано ли действие | `room.game.turn.turn.actionUsed` |
| Станция первого игрока | `room.game.players[0].station` |
| Станция второго игрока | `room.game.players[1].station` |
| Уровни станции | `room.game.players[0].station.levels` |
| Поверхность астероида | `room.game.players[0].station.surface` |
| Отсеки уровня | `room.game.players[0].station.levels[0].compartments` |
| Запасы ресурсов | `room.game.players[0].inventory` |
| Роботы игрока | `room.game.players[0].robots` |
| Производство игрока | `room.game.players[0].productionTasks` |
| Все ракеты | `room.game.rockets` |
| Победитель | `room.game.winnerId` |
| Задачи ремонта | `room.game.repairs` |

Индексы `0` и `1` в массиве `players` соответствуют первому и второму участникам в порядке создания партии.

**Важно:** это пути для JSON-объекта, полученного от сервера. В коде Frontend желательно использовать типы или интерфейсы, а не обращаться к данным без проверки их наличия.

# 9. Правила ходов

Текущая реализация предусматривает:

1. Игроки ходят по очереди.
2. За один ход можно бросить один кубик.
3. За ход можно выполнить одно основное действие.
4. Для перемещения робота используется результат кубика.
5. Ремонт требует времени.
6. Производство ресурсов требует времени.
7. Ракеты перемещаются автоматически при продвижении игровых процессов.

Производство, ремонт и ракеты продвигаются после завершения каждого отдельного хода игрока.

---

# 10. Обработка ошибок

При ошибках Backend возвращает JSON:

```json
{
  "error": "описание ошибки"
}
```

Основные HTTP-коды:

| Код | Значение |
|---|---|
| `200` | Успешный запрос |
| `201` | Комната создана |
| `400` | Некорректный запрос или недопустимое действие |
| `404` | Комната или маршрут не найдены |
| `405` | HTTP-метод не поддерживается |

Frontend должен обрабатывать ошибки и показывать игроку понятные сообщения.

# 11. Рекомендации для разработки Frontend

Предлагаемые экраны:

## Главное меню

- Создание игры.
- Список доступных комнат.
- Подключение по ID комнаты.

## Экран ожидания

- ID комнаты.
- Имя первого игрока.
- Статус ожидания.
- Информация о подключившемся втором игроке.

## Игровой экран

- Игровое поле с двумя станциями.
- Панель ресурсов.
- Роботы.
- Ракеты.
- Текущий игрок.
- Номер хода.
- Кубик.
- Панель доступных действий.
- Информация о производстве и ремонте.

## Рекомендуемая логика интерфейса

1. Получить состояние комнаты.
2. Отобразить игроков и станции.
3. Определить текущего игрока по `currentPlayerId`.
4. Проверить `diceRolled`.
5. Разрешить бросок кубика, если он ещё не брошен.
6. После броска показать результат.
7. Разрешить одно основное действие.
8. После успешного действия обновить состояние.
9. Разрешить завершение хода.

Frontend не должен самостоятельно изменять игровые ресурсы, позиции роботов, время ремонта или состояние ракет.

# 13. Технические замечания

1. Игровые комнаты хранятся в оперативной памяти. После перезапуска сервера партии исчезают.
2. ID игроков пока передаются клиентом. Полноценной авторизации нет.
3. WebSocket пока отсутствует. Для получения обновлений Frontend временно может повторно запрашивать `GET /api/rooms/{roomId}`.
4. CORS необходимо настроить для адреса Frontend перед браузерной интеграцией.
5. Backend является источником достоверного состояния игры.
6. Форматы JSON могут расширяться в ходе разработки.

# 15. Принцип разделения Backend и Frontend

**Frontend:**
- отображает игровое поле;
- показывает игровые объекты;
- обрабатывает действия пользователя;
- отправляет запросы;
- отображает ответы сервера.

**Backend:**
- хранит состояние игры;
- проверяет правила;
- рассчитывает перемещения;
- изменяет ресурсы;
- управляет ходами;
- проверяет игровые действия;
- определяет результат партии.
